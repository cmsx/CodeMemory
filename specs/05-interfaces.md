# Code Memory Service — интерфейсы

## Архитектура: три слоя

- **Core-библиотека** — вся логика: индекс, поиск, ранжирование, capture,
  верификация, tree-sitter.
- **MCP-сервер** — тонкий фронтенд для Клода. Только рабочий набор инструментов.
  Транспорт — **HTTP**: сервер живёт в постоянном контейнере, MCP-клиент
  обращается к нему по сети.
- **CLI** — прямой фронтенд над core: операционка, инспекция, онбординг.

Оба фронтенда работают с `.memory/` и SQLite **напрямую** через core —
отдельного HTTP-API между фронтендами и core нет (по HTTP ходит только
MCP-клиент к MCP-серверу). memory-service живёт в постоянном контейнере:
watcher за кодом держит индекс свежим непрерывно, на старте контейнера индекс
сверяется по хэшам. Запись (`.md` + индекс) атомарна и защищена меж-процессным
локом в `.memory/`.

## MCP — рабочий набор

Восемь инструментов. Набор намеренно мал — каждый инструмент постоянно висит
в контексте Клода. Всё остальное (операционка, онбординг) — в CLI.

### `search`

Поиск заметок. Возвращает компактную выдачу — список `id` + `summary`
(со статусом-пометкой у не-`current` заметок).

- `anchors: string[]` — якоря-фильтры (`file:…`, `symbol:…`, `entity:…`,
  `env:…`); объединяются по OR (union), см. `03`
- `query: string` — текстовый запрос (BM25); термы стеммятся и матчатся
  префиксом, OR по умолчанию, см. `03`
- `strict: bool` — требовать ВСЕ термы запроса (AND) вместо OR по умолчанию;
  сужает шумный OR-невод, выбор режима — за LLM (см. `03`)
- `context: string[]` — рабочий контекст, подтверждающий сигнал (не фильтр)
- `include_archived: bool` — добавить `outdated` к выдаче
- `include_drafts: bool` — добавить `draft` к выдаче (нужен онбордингу для
  дедупликации собственных черновиков)
- `match_all: bool` — вернуть **все** заметки компактной выдачей, без фильтра
  (с учётом `include_archived`/`include_drafts`/`limit`). Штатный параметр, но
  намеренно **не подсвечивается**: его нет в описании MCP-инструмента и в скилле
  `mem`. Рабочий путь — таргетированный поиск; реклама `match_all` там
  спровоцировала бы его как способ срезать угол. Применение — перечисление базы
  при онбординге; о параметре знает скилл `mem-onboarding`.
- `limit: int` — предохранитель

### `get_notes`

Разворот 1..N заметок.

- `ids: string[]` — короткие хэш-ID заметок

Для каждой заметки возвращает: тело, карту якорей всех типов
(`file`/`symbol`/`entity`/`env`, сгруппирована по весу, со stale-статусом),
блок «Упомянутые заметки» по ссылкам `[[id]]` из тела.

### `create_note`

Capture новой заметки.

- `summary: string`
- `body: string`
- `anchors: {uri, weight}[]`
- `status: enum` — дефолт `current` (интерактивный capture; онбординг передаёт
  `draft` явно)

`id` на вход не принимается — сервер генерирует короткий хэш (5 символов) и
возвращает его в ответе. LLM использует возвращённый ID для ссылок `[[id]]`.

Отклоняется, если якорь `entity:` ссылается на незарегистрированную сущность.

Если якоря заметки покрывают только одну ось — нет ни одного `entity:` либо
нет ни одного `file:`/`symbol:` — ответ дополняется полем `warning`. Это
**мягкий сигнал**, не отказ: заметка создаётся. Проверяется только присутствие
оси (бинарно), не полнота набора якорей и не гранулярность класс-vs-метод —
это суждение автора и не форсируется. Недо-якоривание — самый частый дефект
capture (особенно при онбординге), и warning возвращает его прямо в момент
создания, на глаза и LLM, и человеку при review.

### `update_note`

Частичное редактирование заметки: тело, якоря, смена статуса (в т.ч. →
`outdated`).

- `id: string`
- остальные поля — частично

### `rename_anchor`

Обновляет URI якоря во всех заметках при рефакторинге.

- `old_uri: string`
- `new_uri: string`

### `create_entity`

Регистрация доменной сущности в реестре.

- `name: string`
- `description: string`

### `list_entities`

Реестр доменных сущностей (`name` + `description`) — доменная карта.

### `list_symbols_in_file`

Символы файла без чтения файла.

- `path: string`

Возвращает: имя символа, вид, родитель, диапазон строк.

## CLI

Прямой фронтенд над core. Запуск без аргументов → интерактивный TUI; запуск
с подкомандой → one-shot операция.

### Операционные команды

| Команда | Назначение |
|---------|------------|
| `reindex [--notes\|--code\|--all]` | Пересборка производного индекса. Дефолт `--all` |
| `verify [note-id]` | Явная верификация якорей — всех или одной заметки |
| `stats` | Метрики: число заметок, stale-якоря и т.п. |
| `entity update <name>` / `entity remove <name>` | Поддержка реестра сущностей |

### Инспекция / CRUD

Минимальная поверхность, чтобы видеть базу так, как её видит LLM.

| Команда | Назначение |
|---------|------------|
| `note list [--status --entity --anchor]` | Компактный список — как выдача поиска |
| `note show <id…>` | Точный вывод `get_notes`: тело + карта якорей + stale + блок `[[id]]` |
| `search <query> […]` | Прогон поиска, ранжированная выдача глазами LLM |
| `note edit <id>` | Открыть `.md` в `$EDITOR`, затем reindex |
| `note delete <id>` | Удалить заметку, затем reindex |
| `note create` | Интерактивное создание (горячий capture — через MCP) |
| `entity list` / `entity show <name>` | Реестр сущностей |

### TUI-навигатор

Запуск CLI без аргументов. Это **навигатор** (чтение + переходы), не редактор:

- список заметок стрелками, Enter — открыть;
- открытая заметка — LLM-facing вид (тело + карта якорей + блок `[[id]]`);
- переход по ссылке `[[id]]` — Enter на ссылке;
- переход по якорю — Enter на `entity:`/`file:`/`symbol:` в карте → заметки
  по этому якорю;
- поиск изнутри, история переходов (назад).

Мутации делегируются наружу: `e` — открыть `.md` в `$EDITOR`, `d` — удаление
с подтверждением. Форм редактирования в TUI нет.

Ходьба по якорям в TUI воспроизводит retrieval так, как его делает LLM — это
основной инструмент отладки отсечки и ранжирования. Поэтому в видах поиска
и обхода якорей по умолчанию показывается только `current` — как в дефолтном
`search`. Два toggle опционально расширяют выдачу:

- `d` — показать `draft`-заметки (`include_drafts`);
- `a` — показать `outdated`-заметки (`include_archived`).

Оба по умолчанию выключены, состояние видно в строке подсказок. `d` контекстен:
в видах-списках это toggle черновиков, на открытой заметке — удаление. Список
«All notes» показывает все статусы всегда — toggle на него не влияет.

### Онбординг-команды

Онбординг вызывается командой-скиллом `/mem-onboarding`. Своих MCP-инструментов
и CLI-команд у него нет — это skill-driven процесс поверх существующих
MCP-инструментов (`search`, `create_note`, `create_entity`, `update_note`);
из CLI задействован только `reindex` для бутстрапа структурного индекса.
См. `06-onboarding.md`.
