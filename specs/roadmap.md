# Code Memory Service — план реализации

Логика порядка: core — фундамент, MCP и CLI поверх него тонкие. CLI делается
раньше MCP, чтобы получить инструмент инспекции и начать dogfooding.
Watchers, TUI и онбординг — после функционального MVP.

## Этапы

### 0. Каркас

TS-проект, структура `core` / `mcp` / `cli`, tsconfig, зависимости, Dockerfile,
тест-раннер. Пустые скелеты.

### 1. Хранилище заметок и индекс

- SQLite-схема (`02-data-model.md`): notes, anchors, entities, FTS5.
- Note store: разбор/запись `.md` + frontmatter, атомарная запись.
- Index layer: зеркалирование заметок в SQLite, content-hash, реконсиляция
  на старте.
- Реестр сущностей (`entities.md` ↔ таблица).

→ кладёшь `.md` в `.memory/notes/` — он попадает в индекс; правишь —
переиндексируется.

### 2. Структурный индекс

tree-sitter, `symbol_index` и `file_index`, инкрементальность по content hash,
полный бутстрап при пустом индексе.

→ `symbol:`-якоря резолвятся.

### 3. Поиск, ранжирование, верификация

- `search`: якорный + текстовый (BM25), механизмы отсечки, ранжирование.
- `get_notes`: тело + карта якорей + блок `[[id]]`, парсинг `[[id]]`.
- Anchor verifier: stale-детекция.

→ core-retrieval работает целиком.

### 4. Запись через core

`create_note` / `update_note` / `create_entity` / `rename_anchor`; строгий
reject незарегистрированной сущности; меж-процессный lock-файл.

→ полный CRUD на уровне core.

### 5. CLI

`commander`: `reindex`, `verify`, `stats`, `note list/show/search/edit/delete`,
`entity`.

→ система инспектируема и используема руками — первый dogfooding.

### 6. MCP-сервер

8 инструментов поверх core, транспорт HTTP, подключение к Claude Code.

→ **функциональный MVP — Клод пользуется памятью.**

### 7. Watchers

`chokidar`, два независимых watcher'а, дебаунс ~500 мс, пересчёт `anchor_status`
затронутых якорей.

→ индекс свежий непрерывно, пока живёт контейнер.

### 8. TUI

`Ink`-навигатор: список заметок, разворот, переходы по `[[id]]` и якорям,
поиск изнутри, история переходов.

### 9. Скилл

`.claude/skills/code-memory/SKILL.md` по `07-skill.md`.

→ Клод вызывает память вовремя.

### 10. Онбординг

Skill-флоу, scratch-файл `.memory/onboarding.md`, прогон на реальном проекте.

## Границы

- Этапы 1-4 — чистый core, тестируются изолированно.
- После этапа 6 система рабочая.
- Этапы 7-10 — улучшения и обвязка.
