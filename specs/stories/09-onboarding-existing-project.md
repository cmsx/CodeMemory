# Story 09 — Онбординг существующего проекта

## Контекст

Подключаю Code Memory Service к проекту, который уже давно в разработке и у
которого накоплены собственные спецификации в `docs/`.

## Сценарий

Добавляю блок `service` в `docker-compose.yml` проекта — контейнер поднимается,
индексирует код (структурный индекс через tree-sitter).

Запускаю онбординг-флоу скилла. Сначала объясняю логику преобразования: «спеки
лежат в `docs/`, секция уровня `##` = одна заметка». Клод предлагает доменные
сущности, выведенные из структуры кода, — прорежаю список, одобренные
регистрируются через `create_entity`.

Дальше скармливаю спеки **частями**. На каждый чанк Клод `search`-ит хранилище:
новое знание → `create_note(status=draft)`, пересечение с уже созданным →
`update_note`. Сырой текст чанка сбрасывается перед следующим, но заметки
остаются в хранилище и находятся поиском — оно работает как сквозная память.

Прогресс пишется в `.memory/onboarding.md` — на следующий день продолжаю
с того же места. В конце просматриваю `draft`-заметки и промотирую проверенные
в `current`.

## Результат

Существующие знания перенесены в проверяемую форму. Дальше память растёт
органически — обычным capture в живых сессиях.
