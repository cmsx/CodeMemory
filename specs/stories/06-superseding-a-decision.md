# Story 06 — Новое решение отменяет прежнее

## Контекст

Полгода назад приняли решение хранить сессии в Redis с TTL 24 часа. После
инцидента с падением Redis в проде решаем перейти на DB-backed sessions
с Redis как L1-кешем.

## Сценарий

После завершения работы прошу: «сохрани, это отменяет прежнее решение про
сессии в Redis».

Клод сначала ищет старую заметку — `search(query="sessions Redis",
anchors=["entity:Session"])`. Находит. Затем:

- `create_note` новой заметки со статусом `current` — с рассуждением, почему
  ушли от Redis;
- `update_note` старой заметки — статус меняется на `outdated`.

Дефолтный поиск теперь возвращает только новую. Старая доступна с
`include_archived`. Связь между ними — через общий якорь `entity:Session`,
отдельных ссылок-указателей нет.

## Результат

Актуальное знание чистое — в обычной выдаче только новое решение. История не
потеряна: через год на вопрос «почему DB-backed, а не Redis» можно поднять обе
заметки по сущности с архивом и увидеть переход.
