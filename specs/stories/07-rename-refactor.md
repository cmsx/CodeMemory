# Story 07 — Рефакторинг: переименование с обновлением якорей

## Контекст

Метод `DocumentStatusService::transition` решено переименовать в `setStatus` —
короче и понятнее. На него ссылаются несколько заметок с инвариантами статусных
переходов.

## Сценарий

Прошу Клода переименовать метод везде.

Клод правит код. Сразу после успешного переименования — обязательный шаг скилла:
`rename_anchor` со старого URI
(`symbol:app/Services/DocumentStatusService.php::DocumentStatusService.transition`)
на новый (`…::DocumentStatusService.setStatus`). Сервис обновляет URI во всех
заметках, где он встречался, и возвращает их список.

Клод сообщает: «переименовал в коде и обновил якоря в трёх заметках: …».

**Если переименование сделали мимо скилла** (ручная правка, IDE-rename): при
следующем `get_notes` якорь придёт со статусом `stale`. Клод покажет это
пользователю и предложит `rename_anchor` вручную.

## Результат

Накопленное знание переживает рефакторинг — связь заметок с кодом не рвётся.
