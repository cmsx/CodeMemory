# Code Memory Service — доменная модель

Сервис хранит структурированные знания о кодовой базе и даёт находить их быстро,
не перечитывая весь код и документацию. Цель — сохранять контекст между сессиями
и давать LLM погружаться в нужную область, а не загружать всё подряд.

Три первоклассные сущности.

## Заметка (Note)

Запись знания о коде. Отвечает на вопрос «как и почему пришли к этому коду» —
в отличие от самого кода и docstring'ов, которые отвечают «как этим пользоваться».

По форме заметка может быть решением по эпизоду работы, инвариантом (стоячим
правилом), наблюдением-подводным-камнем или разбором чужого кода. Это не отдельные
типы и не поля — только разные формы тела; система их не различает структурно.

Заметку создаёт LLM в момент с горячим контекстом — после задачи, отладки или
исследования, когда понимание ещё полное. Связь с кодом — только через якоря.

## Якорь (Anchor)

Единственное связующее звено системы. Ссылка от заметки к чему-то идентифицируемому
в проекте. У заметки произвольное число якорей; каждый якорь принадлежит ровно
одной заметке.

Якорь несёт **вес** — насколько эта связь важна для данной заметки. Вес — основной
рычаг, удерживающий заметку от всплытия во все упоминания.

Якорь — поисково-индексная машинерия: используется для поиска и индексации,
в контекст LLM сам по себе не выгружается. Поэтому число якорей значения не имеет,
значение имеет только их разметка по весу.

Четыре типа целей:

- **файл**
- **символ** — класс, метод или функция
- **доменная сущность**
- **переменная окружения**

Решения по схеме БД отдельного типа якоря не получают — они привязываются к символу
ORM-модели/сервиса или к файлу миграции.

## Доменная сущность (Domain Entity)

Поименованный концепт предметной области — Order, Cart, Wizard. То, в терминах чего
команда говорит о продукте, а не о коде. Сквозная ось поиска: завязывает на себя
модели, сервисы, контроллеры.

Сущности — **закрытый словарь**, объявленный явно, с кратким описанием «что это
и зачем». Новая сущность не появляется автоматически: при попытке сослаться на
незарегистрированную создание заметки отклоняется — сущность сначала добавляется
в реестр. Это защищает главную ось поиска от расползания синонимов
(`Wizard` / `wizard` / `OnboardingFlow` / `multi-step-form`).

Структурных связей между сущностями нет. Связь между сущностями — это заметка,
привязанная якорями к обеим.
