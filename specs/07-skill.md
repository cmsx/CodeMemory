# Code Memory Service — скилл

Знание о коде на стороне Клода держат два скилла:

- `mem` — основной. Ambient-часть (триггер автозагрузки в `description`)
  отвечает за **чтение**: учит использовать память по фазам работы. Capture
  вызывается явной командой `/mem` — проактивно скилл заметки не создаёт. Имя
  `mem`, а не `memory`: `/memory` занята системной командой.
- `mem-onboarding` — команда `/mem-onboarding`: разовый онбординг существующего
  проекта (см. `06-onboarding.md`).

Сервис даёт *инструменты*; скилл учит Клода **когда** ими пользоваться и **как**
оформлять capture. Без скилла инструменты есть, но не вызываются вовремя.

## Использование памяти по фазам работы

**Планирование и подготовка реализации — поиск в памяти обязателен.** Память
держит контракты, инварианты, edge-кейсы и прежние решения, которые определяют
работу и не видны в коде и сигнатурах. Оценка объёма задачи, разбор плана,
выбор подхода не завершены, пока память не опрошена. Здесь искать широко —
якоря `entity:` и `file:` охватывают горизонт, чтобы не проскочить нюанс.

**Зона поиска не фиксируется на старте.** Каждая новая область, в которую
уходит работа или обсуждение, — отдельный обязательный поиск, до `grep` и
чтения кода. Не считать, что первый поиск под исходную тему покрыл ответвления;
при расширении темы — переискать под новую область.

**Реализация — память доступна, но не пошаговый шлюз.** Когда объём работы
понят, не дёргать поиск на каждый символ. Важные решения живут в памяти: перед
нетривиальной правкой и когда под вопросом контракт или инвариант — свериться.

Порядок поиска: **сущность** (широкая карта) → **текст** (сужение по симптому)
→ **файл** → **символ** (точно, перед правкой). В текстовом поиске стоит
пробовать 1-2 переформулировки.

Текстовый `query` — на языке заметок (FTS матчит буквально, запрос на чужом
языке не найдёт ничего). Русские термы стеммятся и матчатся префиксом на
стороне поиска — писать обычными словами, корни вручную не подбирать. Термы
соединяются OR по умолчанию (нечёткий recall); `strict: true` переключает на
AND, когда OR-невод шумит — механика в `03`.

## Как читать выдачу

- Компактный список (`id` + `summary`) — прочитать целиком, выбрать релевантное
  по `summary`.
- `get_notes` по выбранным `id` — одним вызовом для нескольких.
- Карта якорей развёрнутой заметки — координаты для чтения кода.
- Блок «Упомянутые заметки» — решить по `summary`, дозагружать ли `[[id]]`.
- `stale`-якорь в выдаче — показать пользователю, не игнорировать.

## Когда сохранять — capture

Capture не проактивен — запускается явной командой `/mem` (пользователем или
из рабочего воркфлоу).

Поводы (см. `04-note-authoring.md`): решение по ходу реализации, нетривиальная
отладка, edge case, факт из практики которого нет в доках, архитектурное
решение, исследование незнакомого кода.

Сформировать черновик, `search` по тем же якорям (если заметка уже есть —
`update_note`, не дубль), вызвать `create_note`, показать результат
пользователю на review, после подтверждения зафиксировать.

## Шаблоны тела

- **Обычная заметка (ADR)** — Контекст · Решение · Альтернативы · Инварианты
  (Must Hold) · Антипаттерны и Подводные камни (Must Not) · Пробелы и
  ограничения.
- **Investigation** (разбор незнакомого кода) — Контекст · Подтверждено · Гипотезы
  · Инварианты (подтверждённые) · Пробелы.

Канонические имена секций и критерии классификации — `04-note-authoring.md`.

`summary` пишется как ответ на «что заставит будущего агента открыть заметку
целиком». Веса якорей — по `04`; `critical` ставится скупо.

## Рефакторинг

После переименования символа или файла — **обязательно** `rename_anchor(old, new)`,
чтобы связь заметок не превратилась в `stale`.

## Незарегистрированная сущность

`create_note` отклонён из-за якоря на незнакомую сущность → предложить
пользователю регистрацию через `create_entity` с кратким описанием, после
подтверждения повторить `create_note`.

## Происхождение знания

При выдаче заметки со статусом `draft` или с секцией `Гипотезы` — явно
пометить это в ответе пользователю: «по непроверенной заметке / по гипотезе —
проверьте перед действием».

## Антипаттерны

- Дёргать поиск на каждый символ при реализации, когда объём работы уже понят.
- Разворачивать весь список вместо выбора по `summary`.
- Создавать заметку без рассуждения (переименование, опечатка).
- Пересказывать в заметке дифф или документацию фреймворка.
- Игнорировать `stale`-якорь.
- Помечать `critical` рядовое решение.
