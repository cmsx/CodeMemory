# Code Memory Service — скилл

Скилл — файл `SKILL.md` на стороне Клода (`.claude/skills/code-memory/`)
с YAML-frontmatter (`name` + `description`-триггер автозагрузки) и
markdown-телом инструкции.
Сервис даёт *инструменты*; скилл учит Клода **когда** ими пользоваться и **как**
оформлять capture. Без скилла инструменты есть, но не вызываются вовремя.

## Когда искать — триггеры

- **Начало планирования задачи** → `list_entities` (доменная карта), затем
  `search` по теме.
- **Пользователь упомянул доменную сущность** → `search(anchors=["entity:Name"])`.
- **Перед правкой файла** → `search(anchors=["file:path"])`.
- **Большой файл** → `list_symbols_in_file`, затем точечный `Read` диапазона
  нужного символа — не чтение файла целиком.
- **Работа с env** → `search(anchors=["env:VAR"])`.

Порядок при разборе задачи: **сущность** (широкая карта) → **текст** (сужение по
симптому) → **файл** → **символ** (точно, перед правкой). Каждый шаг у́же.
В текстовом поиске стоит пробовать 1-2 переформулировки.

## Как читать выдачу

- Компактный список (`id` + `summary`) — прочитать целиком, выбрать релевантное
  по `summary`.
- `get_notes` по выбранным `id` — одним вызовом для нескольких.
- Карта якорей развёрнутой заметки — координаты для чтения кода.
- Блок «Упомянутые заметки» — решить по `summary`, дозагружать ли `[[id]]`.
- `stale`-якорь в выдаче — показать пользователю, не игнорировать.

## Когда сохранять — capture

Поводы (см. `04-note-authoring.md`): решение по ходу реализации, нетривиальная
отладка, edge case, факт из практики которого нет в доках, архитектурное
решение, исследование незнакомого кода.

Перед закрытием задачи — сформировать черновик, вызвать `create_note`, показать
результат пользователю на review, после подтверждения зафиксировать.

## Шаблоны тела

- **Обычная заметка** — Что сделано · Ключевые решения и почему · Что пробовали
  и отбросили · Подводные камни · Ограничения.
- **Investigation** (разбор незнакомого кода) — Verified · Hypothesis ·
  решения/камни при наличии.

`summary` пишется как ответ на «что заставит будущего агента открыть заметку
целиком». Веса якорей — по `04`; `critical` ставится скупо.

## Рефакторинг

После переименования символа или файла — **обязательно** `rename_anchor(old, new)`,
чтобы связь заметок не превратилась в `stale`.

## Незарегистрированная сущность

`create_note` отклонён из-за якоря на незнакомую сущность → предложить
пользователю регистрацию через `create_entity` с кратким описанием, после
подтверждения повторить `create_note`.

## Происхождение знания

При выдаче заметки со статусом `draft` или с секцией `Hypothesis` — явно
пометить это в ответе пользователю: «по непроверенной заметке / по гипотезе —
проверьте перед действием».

## Антипаттерны

- Звать поиск на каждый тривиальный шаг — поиск имеет ограниченные триггеры.
- Разворачивать весь список вместо выбора по `summary`.
- Создавать заметку без рассуждения (переименование, опечатка).
- Пересказывать в заметке дифф или документацию фреймворка.
- Игнорировать `stale`-якорь.
- Помечать `critical` рядовое решение.
