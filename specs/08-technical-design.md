# Code Memory Service — техническое видение

Описывает стек и устройство компонентов. Детали реализации конкретного кода
намеренно опущены — это видение, не имплементация.

## Стек

- **TypeScript на Node.js 24.**
- **MCP** — официальный SDK (`@modelcontextprotocol/sdk`), транспорт **HTTP**.
- **SQLite** — `better-sqlite3`: синхронный (удобно для CLI и stdio-сервера),
  зрелый, FTS5 в комплекте. Альтернатива — встроенный `node:sqlite`.
- **tree-sitter** — `web-tree-sitter` (WASM, без нативной сборки под каждую
  платформу) плюс WASM-грамматики нужных языков.
- **File watching** — `chokidar`, два независимых watcher'а.
- **Frontmatter** — `gray-matter` (разбор YAML-шапки заметок).
- **CLI** — `commander` для one-shot команд; **TUI** — `Ink`.
- **Векторный слой** (`sqlite-vec`) — отложен, схема остаётся совместимой.

## Компоненты

### Core-библиотека

Вся логика, не знает ни про MCP, ни про CLI:

- **Note store** — чтение/запись `.md` с frontmatter; атомарная запись
  (`.tmp` → обновление индекса в транзакции → atomic rename).
- **Index layer** — SQLite по схеме из `02`, режим WAL, FTS5.
- **Structural indexer** — tree-sitter; инкрементально по content hash.
- **Search / ranking** — отсечка членства + `weight × idf × text_relevance`.
- **Anchor verifier** — резолв якорей: `symbol`/`file` — SQL и stat,
  `env` — парсинг `.env`, `entity` — реестр.
- **Watchers** — два, с дебаунсом ~500 мс.

### MCP-сервер

Тонкий фронтенд: 8 инструментов из `05`, транслирует вызовы в core.

### CLI

`commander` для команд + `Ink` для TUI-навигатора. Прямой фронтенд над core.

## Индексация

- **Реконсиляция на старте контейнера.** Сервис при запуске сравнивает content
  hash файлов с `file_index` и переиндексирует расхождения — ловит правки,
  сделанные пока контейнер был выключен. CLI делает то же при своём запуске.
- **Бутстрап.** При пустом индексе — полная индексация всего проекта.
- **Watcher на код** → изменённый файл переиндексируется tree-sitter'ом,
  его символы в `symbol_index` переписываются целиком (delete + insert).
- **Watcher на `.memory/`** → изменённый `.md` перечитывается, его строки
  в note-индексе и FTS обновляются.
- **Пересчёт `anchor_status`** затронутых якорей — при изменении кода, дёшево.

## Атомарность и конкурентность

- Запись заметки атомарна: запись `.tmp` → транзакция SQLite → atomic rename.
- Меж-процессный **lock-файл** в `.memory/` на операции записи (CLI и
  MCP-сервер могут работать одновременно).
- SQLite WAL — параллельные читатели при одном писателе.
- Идемпотентность: повторный `create_note` с тем же `id` — no-op.

## Конфигурация

Отдельного конфиг-файла (`.memory/config.yaml`) нет — настраивать в проекте
нечего:

- **Игнорируемые пути** — индексатор уважает `.gitignore` проекта (`vendor/`,
  `node_modules/`, `storage/` и т.п. уже там). Дизайн и так предполагает git.
- **Языки tree-sitter** — определяются по расширению файла; набор
  поддерживаемых — это грамматики, вшитые в сервис. Файл с неизвестным
  расширением пропускается: его нет в `symbol_index`, но `file:`-якоря на него
  работают.
- **Коэффициенты ранжирования** (множители весов, BM25-пол) — константы в core,
  подбираются эмпирически при разработке, не per-project.

Единственный параметр — **корень индексируемого проекта** — задаётся при
развёртывании (env-переменная и монтирование в `docker-compose.yml`), не
в `.memory/`. Нужен в основном разработчику системы, чтобы прогонять сервис
на разных проектах.

Каталог `.memory/` содержит: `notes/`, `entities.md`, временный `onboarding.md`,
`index.db` (в `.gitignore`), lock-файл.

## Развёртывание

- memory-service — постоянный сервис в `docker-compose.yml` целевого проекта,
  соседний с его контейнерами. Монтирует репозиторий (rw на `.memory/`,
  ro на остальное); корень проекта — env-переменная.
- Транспорт MCP — **HTTP**: Claude Code из своего контейнера обращается
  к сервису по compose-сети по имени (`http://memory:PORT`).
- Один контейнер на проект — свой `.memory/` и свой `index.db`.
- `Dockerfile` лежит в репозитории сервиса. В целевой проект добавляется блок
  `service` в его `docker-compose.yml`; образ собирается локально из SSH-клона
  приватного репозитория либо берётся из приватного Docker-реестра. Блок
  коммитится в проект — память «приезжает» вместе с ним.
- CLI вызывается через `docker compose exec memory <команда>`.
- `.memory/*.md` и `entities.md` — в git; `index.db` и lock-файл — в `.gitignore`.
