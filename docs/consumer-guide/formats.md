# Форматы артефактов

Жёсткие шаблоны артефактов, которые производят и читают скиллы. Модель не
отклоняется от этих форматов и не изобретает свои.

- **Заметки памяти** (ADR / investigation) — канон в `specs/04-note-authoring.md`
  (ролевая структура тела, критерии секций) и `specs/02-data-model.md` (тело как
  часть контракта сервиса). Здесь не дублируется.
- **System-Aware User Story** — шаблон в
  [`user-stories.md`](user-stories.md).
- **Планы** — шаблоны ниже.
- **Файл разведки** (`run-<NN>.md`) — шаблон ниже.

## Индексный файл плана (`plans/<prefix>-00-index.md`)

`status` принимает три значения: `draft` (бэклог — не резолвится, не грузится
`/prime`), `active` (единственный фокус, максимум один), `completed` (закрыт
`/finalize`). Смена фокуса ручная — правкой `status:`.

```markdown
---
feature: <Название фичи>
status: active
created: YYYY-MM-DD
---

# <Название фичи>

## Цель
<Зачем это делается>

## Контекст и ограничения
<Вводные данные, жёсткие лимиты>

## Grounding
### Спецификации
<Указатели на файлы спеки, релевантные плану: путь + однострочник «что там
полезного». Указатель с подсказкой, не пересказ спеки.>
### Память
<Ссылки `[[id]]` на ADR-заметки и полезные якоря (`entity:`/`file:`/`symbol:`/
`env:`), найденные при обсуждении, с кратким пояснением, зачем они здесь.>

## Этапы
- [ ] `<prefix>-01-<slug>.md` — <суть шага>
- [ ] `<prefix>-02-<slug>.md` — <суть шага>

## Решения
<Архитектурные решения, принятые до или во время плана>

## Отклонения
<Отклонения от первоначального плана (пополняется при правке плана /blueprint и в /step-done)>

## Edge cases
<Что нужно не забыть покрыть тестами>

## Открытые вопросы
<Вопросы без ответа>
```

## Файл шага (`plans/<prefix>-NN-<slug>.md`)

```markdown
# Step NN — <Название шага>

## Цель шага
<Что делаем конкретно здесь>

## Затрагиваемые файлы / символы
- `file:path/to/file.php` (Зачем трогаем)
- `symbol:Class::method` (Что меняем)

## Definition of done
- <Метрика успеха 1>
- <Тест-мишени: поведение этапа, достойное теста (из `expected`/`system_reaction`
  связанной истории или `## Цель шага`); этап без поведения —
  migration-only/config/`ui` — отметить исключение явно>

## Связанные истории
<id историй, которые этап обязан удовлетворить (ссылка по id, путь не несущий).
Наличие хотя бы одной — селектор ветки гейта: пусто → тест-гейт; есть → E2E по
истории. Это инвариант формата, а не украшение. Пусто — оставить «—».>
- <story-id>

## Стратегия гейта
<Производна от ## Связанные истории, не свободный выбор. Пусто историй → `test`
(гейт по сырому выводу полного прогона тестов). Есть истории → `e2e` плюс
указатель на механизм запуска приложения и сева precondition — без него E2E-гейт
невозможен.>

## Режим разработки
<Как /work пишет код на этапе. Авторский выбор (не производное от историй):
`standard` (дефолт, он же пусто), `tdd` или `ui`. `standard` → обычный поток:
полная Testing Discipline, тесты пишутся с кодом, без строгого test-first на
новую функциональность (багфиксный Red-Green всё равно действует). `tdd` →
надстройка Red-Green-Refactor: нет продакшн-кода без предварительно падающего
теста, на всю новую функциональность. `ui` → исследовательский UI/вёрстка, где
тест нельзя написать вперёд; проверяется UI-веткой валидации по связанной
истории. Режим независим от стратегии гейта.>

## Подзадачи
- [ ] <Микро-шаг>
- [ ] <Микро-шаг>

## Рабочие заметки
*(Заполняется в процессе работы скиллом /work. ЗАПРЕЩЕНО писать сюда git diff
или пересказ кода. Писать только: с какими проблемами столкнулся, почему тест
упал, какое новое ограничение выявил).*

## Журнал проходов
*(Счётчик-артефакт стоп-крана, заполняется /autopilot. Строка на каждый
non-green проход — дефект валидации или timeout watchdog'а спавна; 3 прохода
без зелёного → стоп и эскалация. Решение «тормозить» читается отсюда, не из
головы оркестратора. Пусто при ручном /work.)*
- проход 1: <вердикт · дефект, если есть>
- проход 2: timeout · <что зависло>

## Отложенные решения
*(Tier-B моки, заполняется /autopilot: что отложено · почему · маркер в коде ·
downstream-зависимость. Обязаны всплыть в финальном отчёте — молча потеряться не
могут. Пусто при ручном /work.)*
- <решение> · <маркер> · <downstream>
```

## Файл разведки (`plans/<prefix>/run-<NN>.md`)

Карта контекста этапа, которую производит `/prepare` и потребляют `/work` и
`/diagnose`. Удерживаемый per-step артефакт: один файл на этап,
`plans/<prefix>/run-<NN>.md` — co-location с прочими per-step артефактами
(`step-<NN>.md`, `diagnose-<NN>.md`). Перезапись допустима только внутри своего
этапа (fix-forward пере-разведывает тот же `NN`); кросс-этапно файлы раздельны и
не затираются. Удаляет `/finalize` в конце прогона, при закрытии плана (не
`/step-done`). Указатели и «почему», не контент: тела заметок и текст спеки не
копируются.

```markdown
# Разведка — Step NN <slug>

## Область
<что делает этап, одна строка из индекса и файла шага>

## Файлы
- `path/to/file` — нужен · <почему актуально> · смотреть `Class.method` / строки NN–MM
- `path/to/other` — не нужен · <почему отсёк>

## Заметки
- [[id]] <summary> — <чем важно для этапа>

## Сущности
- `entity:Name` — <одна строка из доменной карты>

## Проверено и отброшено
- <кандидат или угол поиска> — <почему пусто или нерелевантно>

## Если нужен дорисёрч
<какие зоны карта не покрыла; `list_entities` за полной доменной картой +
текстовый поиск по симптому>
```
